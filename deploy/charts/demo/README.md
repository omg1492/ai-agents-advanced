# Demo Microservices Helm Chart

This Helm chart deploys all four microservices from `config.yaml` to AKS with autoscaling capabilities.

## Structure

```
deploy/charts/demo/
├── Chart.yaml              # Chart metadata
├── values.yaml             # Default configuration values
├── .helmignore            # Files to exclude from chart
├── README.md              # Chart documentation
└── templates/
    ├── deployment.yaml    # Deployment manifests for all services
    ├── service.yaml       # Service manifests for all services
    ├── secret.yaml        # Kubernetes Secrets for credentials
    ├── hpa.yaml          # HorizontalPodAutoscaler for all services
    ├── gateway.yaml      # Gateway API Gateway resource (optional)
    └── httproute.yaml    # Gateway API HTTPRoute resources (optional)
```

## Services Included

All services listen on **port 8000** (configured via PORT environment variable):

- **api-stock**: Stock management API service
- **mcp-chef-services**: Chef services MCP server
- **mcp-public-farmer-tools**: Public farmer tools MCP server
- **mcp-visualization-generator**: Visualization generator MCP server

## Key Features

### Minimal Configuration Variables
Only essential values are configurable:
- `registry`: ACR URL (default: rdapps3f1i.azurecr.io, managed by Terraform)
- `imageTag`: Global fallback image tag (default: latest)
- `replicaCount`: Initial replicas (default: 2)
- `hpa.maxReplicas`: Max autoscaling limit (default: 5)
- `resources`: CPU/memory limits
- `logLevel`: Log level for all services (default: INFO)
- `mcpApiKey`: MCP API key for authentication (generated by Terraform)
- `mcpCorsOrigins`: CORS origins for MCP services (default: *)

**Gateway API Configuration** (optional):
- `gateway.enabled`: Enable Gateway API resources (default: false, set to true by Terraform)
- `gateway.name`: Gateway resource name (default: eg)
- `gateway.className`: GatewayClass to use (default: eg)
- `gateway.proxyConfigName`: EnvoyProxy config name (default: custom-proxy-config)
- `gateway.pipName`: Azure Public IP name (set by Terraform)
- `gateway.resourceGroup`: AKS node resource group (set by Terraform)
- `gateway.ip`: Gateway public IP address for nip.io hostnames (set by Terraform)

Per-service configuration:
- `services[].tag`: Image tag per service (overrides global `imageTag`)
- `services[].external`: Expose service via Gateway API (default: false)

OpenAI configuration (for mcp-visualization-generator):
- `openai.enabled`: Enable OpenAI integration (default: false)
- `openai.apiKey`: Azure OpenAI API key (set by Terraform)
- `openai.model`: Model deployment name (default: gpt-5)
- `openai.baseUrl`: Azure OpenAI endpoint URL (set by Terraform)
- `openai.apiVersion`: API version (default: preview)
- `openai.reasoningEffort`: Reasoning effort level (default: low)

### Hardcoded for Simplicity
- Service names and labels (not parameterized)
- Port number (8000 for all services, set via PORT env variable)
- Health check paths (/health endpoint on all services)
- Namespace (default)
- Environment variables (HOST, PORT, LOG_LEVEL, PYTHONUNBUFFERED)
- nip.io hostname pattern (<service-name>.<gateway-ip>.nip.io)

### Autoscaling Configuration
- **Initial replicas**: 2
- **Maximum replicas**: 5
- **Trigger**: 70% CPU utilization
- **Metric**: CPU-based autoscaling

### Resource Limits
```yaml
limits:
  cpu: 500m
  memory: 512Mi
requests:
  cpu: 100m
  memory: 128Mi
```

### Environment Variables

**Each service declares exactly which environment variables it needs.**

This approach provides maximum clarity and avoids injecting unnecessary variables into containers. Each service's `env` list in `values.yaml` or `helm_values.yaml` contains only what that service actually uses.

**Current Service Requirements:**

1. **api-stock** (FastAPI service):
   - `PORT`: "8000"
   - `LOG_LEVEL`: "INFO"
   - PostgreSQL variables (commented out, set via Terraform if needed):
     - `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`

2. **mcp-chef-services** (FastMCP server):
   - `HOST`: "0.0.0.0"
   - `PORT`: "8000"
   - `MCP_DEFER_DELETE_SECONDS`: "60"
   - `MCP_API_KEY`: From `mcp-credentials` secret
   - `MCP_CORS_ORIGINS`: "*"

3. **mcp-public-farmer-tools** (FastMCP server):
   - `HOST`: "0.0.0.0"
   - `PORT`: "8000"
   - `MCP_DEFER_DELETE_SECONDS`: "60"
   - `MCP_API_KEY`: From `mcp-credentials` secret
   - `MCP_CORS_ORIGINS`: "*"

4. **mcp-visualization-generator** (FastMCP server with OpenAI):
   - `HOST`: "0.0.0.0"
   - `PORT`: "8000"
   - `LOG_LEVEL`: "INFO"
   - `MCP_API_KEY`: From `mcp-credentials` secret
   - `MCP_CORS_ORIGINS`: "*"
   - `OPENAI_API_KEY`: From `openai-credentials` secret
   - `OPENAI_MODEL`: "gpt-5"
   - `OPENAI_BASE_URL`: Set via Terraform (Azure OpenAI endpoint)
   - `OPENAI_API_VERSION`: "preview"
   - `REASONING_EFFORT`: "low"

**Adding a New Service:**

When adding a new service, declare only the environment variables it actually needs:

```yaml
services:
  - name: my-new-service
    image: my-new-service
    tag: latest
    external: true
    env:
      - name: HOST
        value: "0.0.0.0"
      - name: PORT
        value: "8000"
      - name: CUSTOM_CONFIG
        value: "some-value"
      - name: DATABASE_PASSWORD
        valueFrom:
          secretKeyRef:
            name: my-service-credentials
            key: password
```

**Best Practices:**

1. **Explicit is better than implicit**: Each service lists its exact requirements
2. **No common variables**: Avoids injecting unused environment variables
3. **Secrets via secretKeyRef**: Always use Kubernetes secrets for sensitive data
4. **Values match defaults**: ENV values should match service code defaults when possible
5. **Document actual usage**: Check service code to verify which variables are actually read

This design eliminates magic global variables and makes each service's requirements immediately visible.

### Health Checks
- **Liveness probe**: /health endpoint, 30s initial delay
- **Readiness probe**: /health endpoint, 10s initial delay

### Gateway API (Optional)

When `gateway.enabled=true`, the chart creates:
- **Gateway**: Entry point with LoadBalancer using static IP from Terraform
- **HTTPRoute**: One route per service marked with `external: true`

**Hostname-based Routing with nip.io**:
Services with `external: true` are exposed on separate hostnames using the nip.io service, which provides wildcard DNS for any IP address. Each service gets its own hostname without URL path rewriting:

- Service hostname pattern: `<service-name>.<gateway-ip>.nip.io`
- Backend URL: `http://<service>:8000/<path>`

**Example** for `mcp-chef-services` with Gateway IP `51.120.45.67`:
```bash
# Health check
curl http://mcp-chef-services.51.120.45.67.nip.io/health

# MCP endpoint
curl http://mcp-chef-services.51.120.45.67.nip.io/mcp/list

# All paths work directly without rewriting
curl http://mcp-chef-services.51.120.45.67.nip.io/any/nested/path
```

This approach provides clean URLs per service with no path manipulation required.

## Terraform Integration

The chart is automatically deployed to AKS via `helm.tf`:
- Uses AKS kubeconfig for authentication
- Generates random MCP API key (32 chars) shared across all MCP services
- Retrieves Azure OpenAI API key from Cognitive Account
- Sets registry from ACR resource
- Deploys to default namespace
- Creates Kubernetes Secrets for sensitive values (mcp-credentials, openai-credentials)
- Optionally deploys Envoy Gateway and configures Gateway API resources
- Creates static public IP with FQDN for external access

**Service List Management**: The list of services to deploy is defined in `deploy/azure/infrastructure/helm_values.yaml` (not in the chart's `values.yaml`). This allows Terraform to control which services are deployed, their image tags, replica counts, HPA settings, resource limits, and external exposure.

To add or remove services, or change external exposure, edit `deploy/azure/infrastructure/helm_values.yaml` and run `terraform apply`.

**Per-Service Image Tags**: Each service can have its own image tag in `helm_values.yaml`:
```yaml
services:
  - name: api-stock
    image: api-stock
    tag: v1.2.3  # Specific version for this service
    external: false  # Internal only
  - name: mcp-chef-services
    image: mcp-chef-services
    tag: latest
    external: true  # Exposed via Gateway API
```

## Usage

### Manual Deployment
```bash
cd deploy/charts/demo
helm install demo . --namespace default
```

### Via Terraform
```bash
cd deploy/azure/infrastructure
terraform apply
```

### Verify Deployment
```bash
# Check pods
kubectl get pods

# Check services
kubectl get svc

# Check HPA status
kubectl get hpa

# View pod logs
kubectl logs -l app=api-stock

# Get MCP API key
terraform output -raw mcp_api_key

# Verify environment variables in a pod
kubectl exec -it <pod-name> -- env | grep -E "MCP|OPENAI|PORT"

# If Gateway API is enabled, check Gateway and HTTPRoutes
kubectl get gateway
kubectl get httproute

# Get Gateway IP and example URLs (via Terraform)
terraform output gateway_ip
terraform output gateway_xip_example

# Test external service access (replace IP with actual gateway IP)
curl http://mcp-chef-services.<GATEWAY_IP>.nip.io/health
curl http://mcp-visualization-generator.<GATEWAY_IP>.nip.io/health
```

### Update Image Tag
```bash
# Update all services to a specific tag
helm upgrade demo . --set imageTag=v1.2.3

# Or update individual service tags in helm_values.yaml and apply via Terraform
# Edit deploy/azure/infrastructure/helm_values.yaml, then:
cd deploy/azure/infrastructure
terraform apply
```

## Design Decisions

1. **Loop-based templates**: Uses `range` over services list for DRY principle
2. **Minimal parameterization**: Only varies what's necessary between deployments
3. **Hardcoded names**: Service names are fixed for clarity and simplicity
5. **Default namespace**: No namespace isolation for demo purposes
6. **ClusterIP services**: Internal-only access (no LoadBalancer costs)
7. **Shared HPA config**: All services use same autoscaling parameters
8. **Common resources**: All services have identical CPU/memory limits
9. **Gateway API optional**: Only deployed when explicitly enabled via Terraform
10. **Path-based routing**: Uses Gateway API's ReplacePrefixMatch for clean URL mapping
