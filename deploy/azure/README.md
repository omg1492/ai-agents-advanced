# Deployment artifacts for Azure deployment

## MCP Tools
Folder `mcp_tools` contains Terraform manifest to deploy MCP Servers into Azure Container Apps. For purpose of our course this is provided by teacher so you do not have to deploy your instance (but you can).

## Azure Infrastructure
Folder `infrastructure` contains Terraform manifests to deploy complete production infrastructure in Azure. Components include:

### Core Infrastructure
- **Azure Kubernetes Service (AKS)**: Container orchestration with Azure CNI overlay networking
- **Azure Database for PostgreSQL**: Managed database service (flexible server)
- **Azure Container Registry (ACR)**: Private Docker image registry
- **Azure AI Foundry**: gpt-5 model with Application Insights observability
- **5 Static Public IPs**: Pre-allocated for LoadBalancer services (deterministic networking)

### Deployed Services
- **dreamfarm-agent**: Main application agent (LoadBalancer, port 8001)
- **keycloak**: Identity provider (LoadBalancer, port 8080)
- **mcp-chef-services**: Chef agent MCP server (LoadBalancer, port 80)
- **mcp-public-farmer-tools**: Farmer tools MCP server (LoadBalancer, port 80)
- **mcp-visualization-generator**: Visualization MCP server (LoadBalancer, port 80)
- **api-stock**: Stock data service (ClusterIP, internal only)
- **chef-agent**: Chef functionality (ClusterIP, internal only)

### Key Features
- Service-specific Helm templates (no generic templates)
- Kubernetes secrets for all sensitive values (secretKeyRef pattern)
- HPA autoscaling for all services (CPU-based)
- Automated test environment generation (Terraform-generated .env)
- Static IP pre-allocation for deterministic service endpoints

## Docker Build
Folder `docker_build` contains configuration and scripts for building and pushing Docker images to ACR:
- `config.yaml`: Service definitions and build configuration
- Build script orchestrates multi-service Docker builds

## Tests
Folder `tests` contains test artifacts:
- `.env`: Auto-generated by Terraform with service IPs and credentials
- `.env.sample`: Template for manual configuration (documentation only)
- Test scripts can use generated .env for integration testing

## Deployment Workflow

1. **Prerequisites**:
   - Terraform installed
   - Azure CLI authenticated
   - Tavily API key obtained from https://tavily.com

2. **Build Docker Images**:
   ```powershell
   cd docker_build
   # Run build script (builds chef-agent, dreamfarm-agent, and other services)
   python build_and_push.py
   ```

3. **Deploy Infrastructure**:
   ```powershell
   cd infrastructure
   # Set Tavily API key
   $env:TF_VAR_tavily_api_key="your-tavily-api-key"
   
   # Deploy
   terraform init
   terraform plan
   terraform apply
   ```

4. **Test Environment**:
   After deployment, Terraform generates `tests/.env` with:
   - All service IPs (5 LoadBalancer IPs)
   - MCP API key
   - OpenAI configuration
   - PostgreSQL credentials
   - Keycloak admin password
   - Tavily API key

5. **Access Services**:
   - Dreamfarm Agent: `http://<dreamfarm-agent-ip>:80`
   - Keycloak: `http://<keycloak-ip>:80`
   - MCP Services: `http://<mcp-service-ip>/mcp`
   - Internal services: Use `kubectl port-forward`

## Architecture Pattern

This deployment follows the **service-specific template pattern**:
- Each service has dedicated deployment.yaml, service.yaml, hpa.yaml
- No generic templates or special case logic
- Terraform controls dynamic values (IPs, credentials, endpoints) via set blocks
- Helm templates contain hardcoded static configuration
- All sensitive values via Kubernetes secrets
